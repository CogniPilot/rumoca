# SPEC_0040: IR Stage Contract Catalog

## Status
REFERENCE

## Summary

Lookup catalog of the Flat, DAE, Solve, structural-lowering, and target-product
contracts referenced by [SPEC_0007](SPEC_0007_IR_PIPELINE.md).

## How To Use This Catalog

This annex holds no rules of its own. Every requirement below belongs to
SPEC_0007 and is **normative by reference from SPEC_0007**; the owning
section in SPEC_0007 states the governing requirement and links here. Cite rows
by their catalog ID (`DAE-C07`, `SOLVE-C13`, `STRUCT-T04`) so a reviewer can
find the exact obligation without loading the whole pipeline spec. Target
product requirements use §4.

## Specification

### 0. Flat Stage Contract Catalog (SPEC_0007 Stage 2)

| ID | Rule | Where | Why |
|---|---|---|---|
| FLAT-C01 | Under MLS §4.4.4, §12.3, and §18.6, a scalar constant or evaluated-parameter binding may become a literal only after proving every referenced occurrence fixed and non-changeable, transitively, and evaluating it through the shared pure-function interpreter. References use exact instance and declaration identity. Cycles, unsettled initialization, unresolved occurrences, and evaluation failures retain the binding. ### 1. DAE Stage Contract Catalog (SPEC_0007 Stage 3)

| ID | Rule | Where | Why |
|---|---|---|---|
| DAE-C01 | No source temporal operators (`pre`, `edge`, `change`, `sample`, `previous`) survive in f_x, f_z, f_m, f_c, relations, or initialization equations | DAE lowering rewrites them into Appendix B constructs: explicit `__pre__.*` inputs, relation/c variables, scheduled events, clock metadata, and ordinary equations over `v` | MLS Appendix B states the DAE as functions over `v` and `relation(v)`; source temporal operators are not computable DAE/Solve graph nodes |
| DAE-C02 | `der(x)` denotes a state-derivative coordinate | MLS Appendix B includes `ẋ` in `v`; DAE keeps that coordinate explicit and structural analysis matches it to the owning state | Source derivative syntax must resolve to a declared state coordinate |
| DAE-C03 | No `initial()` in f_x/f_z/f_m/f_c | initial phase is handled separately | Avoids mixing initialization into runtime equations |
| DAE-C04 | `pre(z)` / `pre(m)` are typed coordinates paired with their current `z` / `m` identities | runtime writes their Solve slots at event entry, and clock-associated history only at its owning tick | `pre()` exists only in AST and Flat; MLS §16 `previous()` history must not advance at unrelated events |
| DAE-C05 | Discrete Real `when` equations remain condition-activated B.1b residuals | ToDAE retains trigger/guard ownership; Solve may reject unsupported coupled systems | An explicit assignment action would silently assume a solved form that B.1b does not guarantee |
| DAE-C06 | `edge(b)` and `change(v)` are equations over typed current/pre coordinates | DAE lowering expands source operators before checked construction | Leaves no event operator for Solve lowering to interpret |
| DAE-C07 | `sample(...)` and clocked `previous(...)` are represented by typed DAE event, clock, and temporal identities plus ordinary equations over current/history coordinates | Runtime scheduling data is explicit DAE ownership; `PreviousId` and typed pre coordinates retain the owning clock without generated-name recovery | Keeps clock semantics at DAE level, compute functions ordinary, and clock history advancing once per owning tick |
| DAE-C08 | `terminal()` is represented by one typed `TerminalCoordinate` and terminal condition activation | The simulation driver writes the derived Solve slot only for the final event at the configured stop time | Preserves MLS §8.6 terminal-event behavior without embedding a phase-sensitive operator or generated parameter name in DAE graphs |
| DAE-C09 | `delay(expr, delayTime[, delayMax])` is represented by a typed `DelayId` plus a checked delay owner containing the source and proof-bearing timing form | Solve lowering derives the runtime slot; the simulation runtime refreshes it from accepted-solution history before evaluating compute graphs | Keeps transport-delay state and interpolation in the runtime while enforcing MLS delay contracts at DAE construction |
| DAE-C10 | `reinit(x, expr)` is lowered into checked guarded state updates during DAE construction | DAE lowering converts state resets into typed target/value updates over current/pre coordinates | Keeps state reset semantics in the event system instead of exposing a source operator to runtimes |
| DAE-C11 | Model `assert(...)` and `terminate(...)` actions are represented as `events.event_actions`, while a default-level function assertion is represented by its checked call-scoped function statement; none are residual/value expressions, and a function assertion may be absent only when its value-proven specialization proves the condition `true` | DAE lowering converts integration-flow statements into guarded event actions with source spans; function-body planning records either the exact proof-erasure decision or constructs the call-scoped assertion owner | Keeps Appendix B compute graphs pure while preserving solver-visible runtime actions and forbidding silent function-assertion loss |
| DAE-C12 | Ordinary discrete Real assignments are prohibited in `events.event_actions` | They construct B.1b residual owners instead | Event actions must not bypass coupled/nonlinear B.1b semantics |
| DAE-C13 | Checked DAE expression constructors cannot represent source temporal or flow-action operators | `rumoca-ir-dae` construction API | The Appendix-B boundary is enforced when a node is introduced, not by a later tree scan |
| DAE-C14 | A Flat structured equation whose checked assignment target is `m` lowers to one authoritative structured B.1c definition carrying its compact domain, target projection, value bodies, activation, provenance, and typed clock ownership | DAE discrete system | A structured Boolean, Integer, String, or enumeration equation must not enter B.1a or acquire parallel scalar owners |
| DAE-C15 | A scalar `initial algorithm` assignment or explicit initial equation `m = value` / `pre(m) = value` for a discrete coordinate lowers to one typed initial-value definition | DAE initialization system | Its checked target/value owner initializes current and pre storage and the claimed equation row cannot also become a numeric residual |
| DAE-C16 | A connection equation joining a B.1b discrete `Real` coordinate to a continuous structural unknown remains a continuous residual, independent of which endpoint flattening places on the left | DAE continuous system | Appendix-B continuous equations may read `z`; consuming the row as a second B.1b owner leaves the continuous connector undefined and makes source balance disagree with the constructed DAE |
| DAE-C17 | Under MLS §4.4 and §8.5, every event-generating occurrence in a runtime binding equation owns the same typed relation, scheduled-time event, or sample clock that the occurrence would own in an equation-section equality | DAE event analysis and the binding's B.1 owner | Binding syntax cannot erase an event boundary needed to refresh the equation; occurrence identity still prevents duplicate owners |
| DAE-C18 | The scalar dependency view of a function result is derived once as exact parameter-scalar/record-field projections and substituted into each call's actual arguments. Each shared function expression is visited once per requested scalar and only the checked binder domain plus its lexical ancestors may distinguish that visit. When a function input controls compile-time projection (for example, an array index), the generic summary is refused and the exact call arguments are projected directly. A function-fold result follows only the requested carried scalar, every concrete point of its compact domain, and transitive carried values its update reads; it does not visit unrelated carried values or scalar coordinates. | `rumoca-eval-dae` dependency projection consumed by structural incidence | Structural analysis remains exact and bounded by the compact function dependency graph instead of repeatedly expanding a nested function DAG, multiplying unrelated sequential-loop contexts, or weakening a specialized call's incidence |
| DAE-C19 | A continuously monitored state relation inside a structured equation family is represented by one compact event family over the checked domain, and Solve derives scalar root programs in canonical domain order. A structured scheduled-time, dynamic-time, or otherwise unsupported event kind is rejected at the exact occurrence instead of constructing the conditional value without its event owner. | DAE event construction and range-preserving scalar-view boundary | MLS §8.5 requires every continuously varying relation occurrence to retain its event boundary; a binder must not erase that obligation or turn one scalar occurrence into the family's owner |
| DAE-C20 | A function conditional that atomically advances several values owns one checked correlation containing its ordered conditions, branch values, fallback values, and resulting definitions. Construction proves that every branch vector is complete and type-compatible and derives each definition's conditional expression from that correlation. Downstream phases consume the correlation directly; they do not reconstruct shared control flow by matching expression shape, provenance labels, or names. | DAE function-body construction and typed view | Retains source evaluation order and call cardinality across aggregate joins while keeping the expression DAG available as the derived value view |
| DAE-C21 | A model-level event algorithm owns one checked transaction spanning all of its discrete Real and discrete-value targets. The transaction retains source statement order, ordered activation/clock topology, exact current/`pre` reaching definitions, aggregate target/value types, and every construction-issued pure-call occurrence used by the sequence. Construction proves unique complete target coverage, each target's exact clock owner, the canonical nonempty set of clocks that can activate the transaction, and that each later statement reads the definition established by the exact preceding statement path before deriving B.1b residual and B.1c value views. Multiple periodic `when` regions in one source algorithm remain one transaction: at an instant where any member clock ticks, only the corresponding regions execute lazily; coincident member clocks execute their regions in source order inside one atomic invocation. Those declarative views remain available for Appendix-B analysis, but downstream executable phases consume the transaction owner and MUST NOT reconstruct it from projected equations, target adjacency, shared call ids, provenance, or expression shape. | Model-event algorithm construction and checked DAE wire replay | A single sampled controller/estimator algorithm cannot become several independently executing output programs, lose sequential or simultaneous semantics across clock/Real/Boolean target classes, execute inactive regions, or require backend memoization to recover one source invocation |

### 2. Solve Stage Contract Catalog (SPEC_0007 Stage 4)

| ID | Rule | Why |
|---|---|---|
| SOLVE-C01 | The deterministic op set — `LoadY`, `LoadP`, `Const`, and math ops — is closed under purity: every op in it is a pure function of `(y[], p[], t)`. The named carve-out is the set of impure exceptions: AD-seed reads (`LoadSeed`, `LoadIndexedSeed`, and `TensorLoad` from `P` with a seed start), external mutable table reads (`TableBounds`, `TableLookup`, `TableLookupSlope`, `TableNextEvent`), and random draws (`ImpureRandomInit`, `ImpureRandom`, `ImpureRandomInteger`). Being outside the deterministic set does not by itself imply impurity: other ops (aggregate/tensor algebra, structured regions, stores, and the `RandomInitialState`/`RandomResult`/`RandomState` state-threading ops) are also pure. Parameter-staticness is the stricter property: SOLVE-C44 refuses to certify any carve-out op parameter-static, and additionally refuses `LoadTime`, which is pure in `(y[], p[], t)` but not constant in `t` | No Modelica-specific ops remain; the purity carve-out is stated, not implied |
| SOLVE-C02 | No source temporal operators (`pre`, `edge`, `change`, `sample`, `previous`) in Solve-IR | Eliminated or represented as explicit DAE metadata before Solve lowering; surviving source temporal operators are upstream bugs |
| SOLVE-C03 | No flow-action calls (`assert`, `terminate`, `reinit`) in Solve-IR scalar programs | `reinit` is already a guarded discrete update; `assert` and `terminate` lower from DAE `events.event_actions` into action metadata plus pure action-condition scalar programs |
| SOLVE-C04 | Solve slots projected from typed DAE pre/previous coordinates hold history values | Runtime writes event-owned pre slots at event entry and clock-owned history slots only when their `ClockId` ticks; generated display names do not define ownership |
| SOLVE-C05 | `initial()` is a typed activation node, never a generic P load in value programs | Runtime phase inputs cannot become ordinary values |
| SOLVE-C06 | A B.1c discrete-valued definition owns source-priority activation/value branches | Preserve assignment priority |
| SOLVE-C07 | No active branch means hold the current target | Inactive assignment semantics cannot be omitted or replaced |
| SOLVE-C08 | B.1b residuals, B.1c definitions, reinit, and condition memory are distinct typed owners | Row-role tags cannot conflate semantics |
| SOLVE-C09 | Pre policy, observation policy, clock owner, and `RuntimeAssignmentRole` derive from each typed owner; the observation policy also certifies whether any selected scalar row reads Y storage and therefore requires algebraic/discrete fixed-point iteration. `RelationFree` rows may consume already-selected relation-memory values, while `RelationEvaluating` rows evaluate a relation, transitively depend on a relation-evaluating owner, or write relation memory. `post_commit_assignment_runtime_rows` is a checked, owner-order projection of `runtime_assignment_rhs` containing exactly the `RelationFree` rows in the typed root-reachable scalar dependency closure, without traversing a `RelationEvaluating` row | Parallel metadata cannot disagree, row indices cannot forge ownership, public observation cannot infer coupling from runtime bytecode, and post-commit settling cannot replay relation evaluation |
| SOLVE-C10 | A B.1c definition computes its first active value or leaves its target unchanged | Gives one local refinement obligation |
| SOLVE-C11 | Event timing is partitioned into root conditions, static arbitrary time instants, dynamic time-event rows, and periodic clock schedules. A periodic clock leaf inside a mixed condition DAG reads a hidden activation lane derived at the current event instant from its typed Solve clock schedule; the lane is not a second clock owner and cannot invent or approximate a schedule. Each lowered root-relation output additionally owns one row-aligned `RootRelationRefreshRole` derived from its typed continuous-algebraic dependencies: `Frozen` requires proof that no such dependency exists; `AlgebraicDependent` requires proof that one exists; unsupported dependency forms fail construction. | `events` owns zero-crossing and one-shot/dynamic time events; `clocks` owns periodic schedules derived from `sample`/clock metadata, including the authoritative value of mixed clock-condition leaves; runtime consumes compiler-issued refresh ownership instead of reconstructing it from scalar bytecode, row position, or model identity |
| SOLVE-C12 | Terminal-event and transport-delay inputs use explicit runtime-managed P-slots | Solve metadata names and computes these inputs; numeric runtimes activate the terminal slot at the stop-time event and refresh delay slots from accepted-solution history |
| SOLVE-C13 | Valid `ComputeBlock`s scalarize via fallible `rumoca-eval-solve::to_scalar_program_block(&block)` | Tensor-agnostic adapters call it and propagate span-bearing metadata errors |
| SOLVE-C14 | Scalarization is a backend/evaluator choice, not an IR or lowering choice | Do not flatten tensor nodes in `rumoca-ir-solve` / `rumoca-phase-solve`; IR crates must not define scalarization helpers |
| SOLVE-C15 | Forward and reverse AD products are Solve artifacts, not base Solve IR fields | Keeps base Solve payloads lean while allowing Rumoca-owned JVP/VJP/adjoint paths for runtime and generated targets |
| SOLVE-C16 | Jacobian products live in `SolveArtifacts`, not base `SolveProblem` | Avoids unconditional AD materialization for codegen/IDE paths that do not consume them |
| SOLVE-C17 | Structural sparsity is derived with `SolveArtifacts`, never accepted as a raw hint | A false-negative pattern can corrupt compressed AD and sparse solves |
| SOLVE-C18 | Mass-matrix form lives in `ContinuousSolveArtifacts`, not DAE | It is solver-facing derived metadata, not canonical Modelica DAE semantics |
| SOLVE-C19 | BLT orderings from DAE-IR MAY drive `ComputeBlock` layout | Reuses upstream structural analysis |
| SOLVE-C20 | Solve lowering preserves a structured B.1c definition as a compact `ComputeNode::Map` (or stronger proven tensor node) plus a compact affine target map; row role, pre mode, observation policy, and clock owner derive from that owner | Scalar programs are produced only by `rumoca-eval-solve` or backend scalar-view APIs under SOLVE-C14; phase lowering never materializes a parallel scalar definition |
| SOLVE-C21 | Every scalar and structured discrete update carries a typed integrator-history effect derived from compiler dependency analysis; `Preserve` proves the update cannot reach continuous dynamics, while state targets and every unknown, cyclic, ambiguous, or unsupported dependency are `Restart` | A runtime may retain multistep history only from compiler-owned evidence joined with actual event changes; model names, row positions, and observed traces are not evidence |
| SOLVE-C22 | A compact event-iteration plan is a reverse bijection over canonical typed, non-input `z`/`m` storage runs and their scalar, structured, or hold producers. Value kind derives from the storage run; clock participation derives from the producer. Wire decode replays these owners and rejects missing, extra, relabeled, overlapping, or scalarized coverage. One complete Appendix-B pass reads a heterogeneous fixed `pre` view: ordinary unclocked `pre(z)`/`pre(m)` advances atomically between passes, while continuous left limits and clocked `previous()` remain at event entry; clocked equations execute only on the first pass. Successful event return proves exact typed equality for every fixed-point run. | Serialized metadata cannot forge the convergence domain, tensor families remain compact, mixed temporal expressions retain their distinct histories, and runtime success witnesses the simulation refinement obligation |
| SOLVE-C23 | A runtime index, slice, or update over a finite checked tensor lowers as one shape-checked aggregate operation with compact dimensions and affine row-major addressing over every base axis. Phase lowering and canonical Solve construction MUST NOT enumerate tensor coordinates into scalar registers, repeated operations, or select chains; a scalar result is only a projection of that aggregate owner. Evaluator and backend boundaries execute or render the compact operation directly, and only a final target-local rendering step may materialize coordinate operations required by the target language. | Rank-n access preserves the tensor's checked shape and one-based Modelica indexing while IR size remains independent of tensor extent |
| SOLVE-C24 | A call whose checked function body owns a call-scoped action lowers only when Solve owns an equivalent action schedule; otherwise the call fails lowering at its exact span | Inlining only the function result would erase `assert` and admit a normal but semantically invalid trace |
| SOLVE-C25 | A call-scoped function assertion in a continuous or unclocked event expression lowers as one call-specialized, activation-guarded root projection plus one activation-guarded assertion-action projection. The root is strictly negative while the call is inactive or its assertion is true and strictly positive exactly while an active call violates the assertion. Those projections consume the exact shared pure-call owner required by SOLVE-C51; they do not rebuild its arguments or function body as independent scalar rows. A clock-owned call lowers one assertion-action projection gated by that clock's typed activation lane, carries that exact periodic clock owner in action metadata, and creates no continuous root; evaluators execute its condition only when the owner ticks, so unrelated events neither evaluate nor fire it. Conditional activation includes every preceding false branch and the selected true branch. A loop-carried or otherwise unrepresentable activation fails lowering at the exact call span. | Preserves function-call assertion timing without inserting side effects into scalar programs, evaluating inactive conditional branches, duplicating a call frame, or claiming a schedule Solve cannot execute |
| SOLVE-C26 | A generated backend may project algebraic residuals into a sequential assignment plan only when every block in the compiler-owned BLT algebraic projection plan is a singleton and the shared target-assignment certificate materializes an exact isolator for that block's declared target. The generated plan preserves BLT order and writes only those certified targets; any missing, coupled, or non-isolable block makes the target unavailable. | Lets explicit-runtime targets refresh algebraics without embedding a nonlinear solver, guessing equation orientation, or accepting stale algebraic storage |
| SOLVE-C27 | Scalar lowering may reuse a completed function-fold result only when the exact function-call context and every active fold read transitively by that fold's initial or update expressions has identical carried values and domain point. An active sibling or ancestor omitted by the checked expression dependency graph does not split the cache identity; every active fold that is read does. Statically proved integer indices and branch conditions project their selected coordinate or branch before runtime selection is emitted; calls and call-scoped actions in statically unreachable branches are not constructed. | Preserves sequential function semantics while preventing repeated tensor-loop expansion from growing with unrelated loop contexts or unreachable function schedules |
| SOLVE-C28 | A non-`sample(u)` periodic definition is rejected as clocked/continuous feedback only when the structurally matched continuous graph plus exactly oriented same-clock discrete definitions proves a directed cycle from that definition's target back to an operand it reads. Explicit `sample(u)` ownership and state derivatives end that same-instant path; sharing a clock or an undirected incidence component is not evidence of feedback. | MLS §16.5.1 prohibits an instantaneous algebraic loop across the clock boundary, but feed-forward task pipelines and connector paths on one release remain schedulable |
| SOLVE-C29 | A model-level `assert` or `terminate` action owned by a periodic clock lowers one action-condition row that combines its checked guard with the clock's typed activation lane; it creates no continuous root and is false at unrelated events | Clocked actions execute exactly on their task release without inventing continuous event surfaces or firing under another schedule |
| SOLVE-C30 | A pure scalar expression already lowered in an ancestor activation context may be reused in a descendant activation context up to, but never across, the nearest function-call boundary. Sibling contexts and distinct calls do not share the value. Any call-scoped assertions were therefore scheduled at the dominating evaluation, and a descendant use does not construct a second assertion whose activation reads the call's own result. While constructing that assertion program only, re-entry into the same exact function and argument expressions reuses the already-bound call frame; ordinary result lowering retains its recursion proof and may not take this path. | Preserves conditional evaluation, caller parameter identity, and call-specialized action timing while preventing a shared call used by both a branch condition and branch value from creating a false recursive lowering cycle |
| SOLVE-C31 | Every scalar function-call frame records the activation-path depth at call entry. Projecting a function parameter into its actual argument suspends the callee frame, scalar context, and exactly the callee-local activation suffix, then restores all three after lowering in the caller context. | A callee branch guard cannot escape through parameter substitution, contaminate a caller argument, or make a parameter from a sibling call appear outside its checked owner |
| SOLVE-C32 | Solve IR is an executable family with distinct `SolveProblem` and `SolveAlgorithmBlock` (pending: 2026-08-08 plan, M3-4) roots over shared typed scalar/tensor vocabulary; no root carries optional fields or mode tags belonging to the other | Root construction excludes nonsensical solver/controller combinations |
| SOLVE-C33 | Every shared register and slot has an exact scalar or aggregate type; Boolean and Integer never travel through Real storage, and Real evaluation uses the root's checked arithmetic profile. That profile carries the Real format and the Integer domain; it carries no rounding field, because every admitted Real operation rounds to nearest, ties to even, on every backend. Operation-level rounding enters as the SPEC_0047 4.3 contract, with the operations that can differ under it | Generated float32 execution cannot disagree with a float64 reference hidden inside the IR |
| SOLVE-C34 | `SolveAlgorithmBlock` (pending: 2026-08-08 plan, M3-4) owns exactly one Startup, Recalibrate, and DoStep method; actions retain statement order, explicit branches, statically bounded loops, calls, stores, limits, signals, closures, and escape sets | Production execution is a checked refinement of Algorithm Code, not template reconstruction |
| SOLVE-C35 | Persistent/interface slots and lexical locals are distinct checked storage classes; every read is dominated by initialization or a prior definition, and local scope/lifetime derives from the action tree | Method scratch cannot inflate persistent state or escape its lexical owner |
| SOLVE-C36 | Aggregate copy, fill, construction, projection, selection, and call transfer remain first-class shape-checked operations with compact domains and alias policy. Constant element projections and slice origins use zero-based checked IR coordinates; runtime element-selection operands retain one-based Modelica coordinates, and that one aggregate operation owns their checked row-major conversion. | Templates and backends cannot scalarize tensors by coordinate enumeration or disagree about the source-to-IR index boundary |
| SOLVE-C37 | Every function call owns a checked calling convention describing input/output passing, storage identity, alias restrictions, evaluation order, and exact result cardinality; renderers only spell this convention | ABI choice cannot be made from rank, names, or template conditionals |
| SOLVE-C38 | Every `SolveAlgorithmBlock` (pending: 2026-08-08 plan, M3-4) method, declaration, operation, action, and call maps injectively to checked Algorithm Code identity and exact provenance; unsupported target-profile behavior prevents root construction | Production artifacts remain traceable to the upstream checked Algorithm Code |
| SOLVE-C39 | A checked DAE function fold lowers as one finite-domain `FunctionFoldProgram` with an explicit typed loop-carried tuple, compact initial/update bodies, exact result projections, and region-owned iteration-local SSA definitions that neither enter nor escape the carried tuple. Phase lowering and canonical Solve construction MUST NOT enumerate the fold domain into repeated scalar operations or substitute a multiply-used iteration-local definition into each use. Evaluator and backend scalar views execute the compact owner directly; they may replace it only with a stronger proved tensor kernel, not reconstruct or cache a value graph after expansion. | Runtime and generated-code cost remains proportional to the function body plus executed iterations, while shared per-iteration work, sequential Modelica function semantics, and empty-domain behavior remain owned by one checked artifact |
| SOLVE-C40 | Conditional function-loop execution remains explicit and lazy. A top-level `GuardedFunctionFold` owns a required checked activation register, whose defining condition is materialized outside the path it guards, and yields its initial carried tuple unchanged when inactive. A condition-owned `StoreOutputFunctionFold` executes its nested fold only on the selected arm while the other arm preserves the matching parent-carried range. An owning guarded fold consumes its inherited activation prefix exactly once; nested folds materialize only guards introduced inside that fold's update while retaining the inherited path for assertion provenance. The checked activation/condition, polarity where applicable, initial sources, capture range, result range, function context, and parent-carried versions are the complete reuse identity. Backends introduce target control flow only at final emission and MUST NOT eagerly evaluate the fold followed by elementwise selection. | Preserves Modelica algorithm branch semantics, prevents a guard expression from recursively guarding itself, makes inactive function calls and assertions unreachable, and prevents disabled tensor estimators from consuming runtime while retaining one compact, auditable fold owner |
| SOLVE-C41 | A tensor transpose owns the first two checked dimensions, the checked product of every trailing dimension as an explicit element width, and an independent arithmetic lane count. Its source and result ranges contain exactly `rows * columns * element_width * lanes` registers. DAE-to-Solve lowering emits one such owner for every legal rank-two-or-greater transpose and MUST NOT enumerate coordinates; forward AD changes only the lane count. | Preserves MLS transpose semantics for higher-rank arrays, prevents trailing tensor shape from being conflated with primal/tangent representation, and keeps construction, evaluation, differentiation, and final lowering auditable from one compact shape proof |
| SOLVE-C42 | One checked DAE multi-target function conditional lowers once per exact call frame to one `FunctionConditionalProgram`. The program owns ordered condition regions, one result region per matching branch, a fallback result region, exact capture ABI, target order, aggregate shapes, and one contiguous result tuple. Conditions execute in source order until the first true value; only that branch's result region executes, and no later condition or unselected result region is evaluated. Compact tensor/fold operations remain inside the selected region and MUST NOT become per-target or per-scalar `Select` graphs. Reuse identity includes the exact call arguments, activation context, conditional identity, capture values, and target tuple. Forward AD evaluates the primal conditions and differentiates only the selected result region; backends introduce branch control flow only at final emission. | Carries DAE's atomic branch correlation into executable Solve IR, preserves Modelica short-circuit algorithm semantics and assertion reachability, prevents repeated estimator graphs across correlated outputs, and makes lazy execution correct by construction rather than trace specialization or post-expansion CSE |
| SOLVE-C43 | A `ScalarProgramBlock` owns each exact function-conditional call frame once in a checked owner table. A scalar-view operation references that owner by an issued block-local id and supplies compact, shape-checked capture and result ranges; it does not embed, clone, enumerate, structurally compare, or rediscover the conditional body. Owner identity contains the DAE conditional identity, ordered function-call arguments, activation and compact-domain context, semantic capture sources, arithmetic/AD profile, and complete target tuple. Construction rejects two payloads or call identities for one id and two ids for one exact identity. Evaluators execute an owner at most once per block invocation and project all referenced results; final backends compile its lazy control-flow body once and may materialize scalar target instructions only there. Wire replay reconstructs the owner table and the same uniqueness/range proofs before exposing the block. | Keeps cost proportional to distinct semantic calls rather than residual projections, prevents serialization and native-code duplication, preserves tensor ranges through the last target boundary, and makes cross-row reuse an explicit proof instead of post-expansion CSE or graph recollapse |
| SOLVE-C44 | A causal refresh row is parameter-static only when construction proves its complete executable owner is independent of time, solver state, dynamic algebraics, external mutable tables, AD seeds, and impure state. `LoadY`/Y-tensor ranges may read only the row's exact target or previously certified parameter-static targets; `LoadP`/P-tensor ranges contribute their exact parameter slots. Runtime may reuse the row only while the complete certified parameter snapshot is bitwise identical and must consume the issued classification and parameter set without rescanning operations. | Extends invariant refresh caching to tensor-native programs without treating compact owners as dynamic merely because they are structured, while preventing stale state/time/event/table values and keeping the reuse proof auditable by construction |
| SOLVE-C45 | Continuous residuals that retain typed `Field` and/or `Index` projections rooted at one identical compiler-issued pure aggregate-call occurrence may lower as one multi-output scalar program. Construction proves that every member is algebraic, owns a unique explicit residual output ordinal, preserves its exact scalar count and projection order, and refers to the same DAE call `ExprId`; it does not compare call bodies or arguments, inspect names/provenance/row adjacency as identity, or recognize an expanded scalar graph. One scalar compiler lowers the aggregate call frame once and emits each residual projection through the block's checked output map. Dependency, assignment-isolation, AD, evaluator, and final-backend consumers select logical outputs by their explicit output offsets and MUST NOT force unrelated projections or reconstruct the group. | Preserves the atomic evaluation and tensor sharing of a source record/aggregate call after DAE equation projection, prevents one expensive pure function body from being rebuilt per record field, and makes reuse an issued semantic identity rather than CSE or post-expansion recollapse |
| SOLVE-C46 | A prepared row that contains compiler-owned lazy aggregate control flow (`FunctionConditional` or `GuardedFunctionFold`) retains that checked owner as the sole branch-specialization authority. The reference evaluator may use a dependency trace to execute the row lazily, but it MUST NOT derive a replacement native program by pruning the surrounding scalar operation graph, converting selected branches to moves, or appending one scalar guard output per observed condition. Native and generated backends compile the original checked aggregate owner directly and preserve its compact capture/result ranges. Trace-derived native specialization remains available only to rows whose branch ownership consists exclusively of ordinary scalar `Select` operations and whose complete ordinary output tuple remains explicit. | Prevents a compact conditional/fold from being expanded, traced, and partially reconstructed after lowering; avoids scalar guard-certificate output explosion; and keeps lazy execution, branch validity, and formal refinement tied to the compiler-issued owner rather than an observed runtime path |
| SOLVE-C47 | In a typed clock-owned guarded assignment group, a source-priority branch guarded by `Always` or by that exact owning `ClockId` is resolved before scalar-program construction: its value is the initial selected owner, the hold fallback and all lower-priority branches are unreachable and are not lowered, and only higher-priority dynamic branches may wrap it. This rule is unavailable to unclocked event rows and to a different clock because their trigger activation remains dynamic. Construction uses the DAE condition and typed clock owner directly and MUST NOT emit `Const(1)` plus per-target `Select`, discover the pattern from scalar operations, or rely on runtime trace specialization. | Preserves clocked-partition semantics while preventing unconditional aggregate update ranges from becoming hundreds of scalar condition/select/fallback graphs; the simplification is semantic and correct by construction at the first owner |
| SOLVE-C48 | Every reachable guarded-assignment branch value lowers inside one exact activation owner containing its typed clock (if any), trigger condition, guard condition, and trigger-memory coordinate. The numerical evaluator selects a full-rank dependent complement before constructing the state map: mandatory source states remain independent, forbidden source values remain dependent, and remaining candidates follow source preferences and declared-state priority. Trial values never become runtime seeds, overrides, or initial equations. Nonconvergence, non-finite values, inconsistent preferences, and singular selected bases fail explicitly. Highest-derivative reconstruction, actual initialization, and subsequent rank loss retain the ordinary checked numerical-kernel obligations. | structural transformation, Solve analysis, numerical evaluation | Coordinate trials cannot redefine initialization or certify global regularity |

STRUCT-T07 constraint-fold chart rows, bound by SPEC_0007's state-selection contract. Switching among charts is tool behavior. MLS 3.7 §4.9.7.1 does not mandate it; it constrains it: every chart honors the `StateSelect` priorities the static selection honors. The group is the deepest (position-level) stage of a reduced selection: its coordinate columns `C` and constraint rows `G`, `|C| > |G|`. A chart splits `C` into integrated columns `I` and reconstructed columns `D`, `|D| = |G|`. Its slope is the dependent Jacobian `g_D`. For one chart, `sigma` is the smallest column-pivoted QR pivot of that chart's reconstruction block, divided by the largest pivot of the same block rows taken over the block columns plus the group's exchange columns. For one row it is `|g_d| / max_j |g_j|`. Every policy number below is a constant of `rumoca_eval_solve::projection_policy`, the single owner every executing kernel reads.

| Rule | Owner/Where | Brief Justification |
|---|---|---|
| Scope: only reduced selections. An index-1 algebraic whose own block Jacobian vanishes (a coordinate the constraint leaves undetermined at an isolated point) is not a chart fold. It keeps its typed projection failure, and no coordinate is differentiated to create an alternate. A definitional first-integral group keeps its mirror enumeration (SPEC_0053 section 2a); exchanges apply to a reduced group that issues no mirror | `rumoca-phase-solve` state selection | Only a reduced basis has an integrated coordinate to exchange; widening to index-1 blocks would differentiate every smooth nonlinear loop |
| A fold-capable dependent is a primary dependent at the group stage whose column choice is an eligible state class: a source state, a `prefer` coordinate, or a demoted `always` coordinate. The group is exempt when its slope is proven constant: every stage equation is affine in its coordinates with coefficients the STRUCT-T03 time-invariance closure proves constant (sums, negations, products and quotients by invariant factors, projections, and arrays; any call or other nonlinear form of a coordinate refuses). A constant slope that is nonsingular at construction never vanishes, so the group issues no alternate and records each ranked exchange as withheld by slope invariance. A state-dependent slope that is nonvanishing by a structural argument (a squared norm plus a positive constant) is not exempted | state selection (`select`, `FormalDerivativeView::stage_slope_is_invariant`) | A loop-closure slope such as `-cos(a1)*cos(a2)*cos(a3)` vanishes on the manifold exactly like a first-integral norm, while a linear loop closure's slope is a constant matrix and cannot |
| An exchange `D - d + i` pairs a fold-capable dependent `d` with a primary independent `i` of the same stage. `i` is not a `StateSelect.always` state, and at least one stage equation owner reads both. Exchanges are ranked by the number of stage equation owners reading both, descending, then by `(d, i)` stage ordinal, ascending. The first `MAX_ALTERNATE_CHARTS_PER_GROUP` (4) are issued. Every other candidate is recorded as withheld by the cap | state selection | The cap bounds code size deterministically; incidence ranking favors the exchanges sharing the most constraint rows, and a recorded withheld list keeps the coverage gap explicit |
| Each issued exchange remaps the primary integrated set at every formal order, from `(source(i), k, scalar(i))` to `(source(d), k, scalar(d))`, and is prepared through the same checked candidate construction as the primary. An exchange is withheld, not fatal, and recorded when any of these holds: its remap has no coordinate, its construction fails, or its lowered solver layout differs from the primary's | state selection and Solve lowering (`attach_alternate_chart_plans`) | Every chart must run in the one solver-Y space the transfer relies on; an inadmissible alternate cannot fail a model the primary compiles |
| Each chart carries a construction-time certificate. It names the reconstructed coordinate by solver-Y slot, and its slope program: the projection block of that chart's own plan containing the reconstructed coordinate, evaluated through the plan's directional AD. Its regular region is `sigma >= sigma_regular`, the recorded singular threshold times `CHART_REGULAR_MULTIPLE` (1e6). The chart set records coverage: issued exchanges, then those withheld by the cap, by construction, or by layout. Trial-point conditioning is recorded and never used to drop an alternate | Solve construction (`ReducedChartSet`) | The runtime evaluates exactly the slope construction named; a gap in coverage is visible in the IR |
| Switching is decided only at an accepted step (`fmi3CompletedIntegratorStep`), on the settled full physical coordinate of that step. Every chart's `sigma` is evaluated in its own runtime at that shared solver-Y point. With active chart `a`, the kernel requests a change to `b` when three conditions hold: `sigma(a) < CHART_SWITCH_KEEP` (0.5), `sigma(b) > CHART_SWITCH_IMPROVEMENT * sigma(a)` (1.5), and `sigma(b) >= sigma_regular`. Among qualifying charts it takes the largest `sigma`, ties to the lowest chart index. A located state event on the same step takes precedence, and the test repeats at the next accepted step | FMI kernel (`dynamic_chart`, `completed_integrator_step`) | Deciding while the active chart is still regular is the SPEC_0053 section 2a obligation; a deterministic tie rule lets any kernel reproduce the choice |
| Hysteresis: after `a` switches to `b`, `sigma(b) > CHART_SWITCH_IMPROVEMENT * sigma(a)` holds, so switching back needs the ratio to swing by at least the square of that factor. No other state is kept, and no chart is re-tested inside Event Mode | FMI kernel | A ratio band without timers cannot chatter at the crossover and needs no extra snapshot state |
| A trial point (an integrator stage, a Newton iterate, an event-location iterate, a rejected step) never changes the active chart. When a component carrying a chart set fails its certified reconstruction there, the derivative handle reports a recoverable trial discard rather than a latched failure. The built-in integrators reject that trial and retry a smaller step; a discard at an accepted point, or step-size underflow, stays a typed failure. If an accepted step settles with `sigma(active) < sigma_regular`, the fold was crossed before a switch could be requested, and the run fails with a typed error; no chart is adopted after the fact | ME derivative handle, built-in integrators, FMI kernel | A switch taken from an unaccepted or already folded point cannot preserve the physical branch |
| The change is one Event-Mode transaction in `fmi3UpdateDiscreteStates`: rebind the active chart; transfer the generated state values from the latched physical coordinate of the accepted step; re-establish every original constraint and the tangent reconstruction with branch-limited certified projection at unchanged tolerances; report `valuesOfContinuousStatesChanged` and `nominalsOfContinuousStatesChanged`; invalidate caches; restart integrator history. A failed transfer restores the pre-transaction chart, states, and caches and reports a typed error, never a partial switch. Integration dimension, observables, and event indicators are unchanged | FMI kernel | A chart change is a representation change of the same physical solution (SPEC_0053 section 2a) |
| The generated C kernel does not yet mirror switching. A model whose chart set carries alternates keeps the existing C refusal (`me_projection.rs`), so its FMU export refuses rather than integrating on one chart. A mirror must read the same policy constants and reproduce `sigma`, the rule, the tie break, hysteresis, trial discard, and transfer | `rumoca-phase-codegen` | Integrating on one chart without the switch would silently fold |
| Evidence covers construction and runtime. Construction unit tests cover exchange enumeration, `StateSelect` admissibility, incidence ranking, the cap and its coverage record, and withheld exchanges. A runtime unit test on a synthetic two-chart plan covers the switch, hysteresis, trial discard, transfer atomicity, and the typed error past a fold. `Constraints.UniversalConstraint` runs to `t = 10` at `atol 1e-10`, matches OMC, and keeps the constrained body within `1e-4` of the jointed body. The index-1 `CardanChartFold` fixture pins its projection failure message | compiler, FMI, and MSL suites | Switching must be shown at the fold, and must cost nothing where no exchange exists |

### 4. Built-in Target Product Contract (SPEC_0007)

| Rule | Required evidence |
|---|---|
| Public names describe artifacts or interface profiles | Target IDs remain meaningful without IR knowledge |
| Consumed IR is a separate manifest dimension | `target.toml` declares `ir`; `rumoca targets` reports it |
| The target has a concrete present-day user workflow | `README.md` names the intended user, input IR, produced artifact, invocation, and the decision or deployment task the artifact supports |
| The target states its semantic boundary honestly | `README.md` and `target.toml` name non-goals, unsupported semantics, readiness, and whether the artifact is source, analysis output, a runtime component, or a standards container |
| The target emits a non-empty artifact | At least one `[[files]]` entry renders through the checked target path; manifest-only future placeholders are prohibited |
| Unsupported input fails closed | Focused negative tests prove that unsupported semantic operations cannot become comments, stubs, zero values, omitted sections, or successful-looking artifacts |
| The artifact is checked at the strongest practical boundary | Unit tests always cover manifest parsing and real rendering; language targets parse or compile; executable targets run a numerical fixture; package/standard targets validate metadata, lifecycle, and execution against the exact claimed revision |
| Documentation and tests are target-local and discoverable | The target `README.md` lists the exact focused tests and external gates that support its readiness claim |
| Experimental status narrows claims, not evidence | A readiness-zero target may expose a pinned experimental interface, but still emits and validates a useful artifact; readiness zero cannot excuse a non-product |

evidence exist. Templates MUST fail with a span-bearing error on an unsupported
checked construct; lossy placeholder text is never acceptable.
