## Runtime and GPU scope

The native scenario test proves compilation of all sixteen exact linked configurations, not their runtime. Runtime is owned by `user_guide_scenarios_smoke.mjs`, consuming the canonical Rust/WASM scenario parser and original model/configuration bytes. Fourteen simulation cells must initialize and produce finite, nonempty, rectangular, ordered samples including every requested output-grid point and endpoint. Interactive cells retain actual configuration parameters, inputs, solver, tolerances and authored interval through `withInteractiveConfiguration`, and advance three intervals. Batch cells use at most three authored output intervals when one is explicit; otherwise they retain the authored/default horizon. Unsupported authored batch tolerances/start settings fail rather than disappear. Two GALEC cells must return all three nonempty production files. These are short runtime checks where bounded, not claims of full authored flight/simulation horizons.

Only the book Wave2D/Airfoil hardware compute path can skip before execution when WebGPU/adapter hardware identity is absent or the adapter is software/fallback. All CPU model compilation, finite CPU samples, checked GPU preparation, Turkey/Balloon/FixedWing WebGL, parameter handoff and sixteen scenario cells stay required on GPU-free workers. Hardware-admitted compute exceptions, timeouts or nonfinite/empty readbacks fail; there is no post-failure skip or CPU fallback pretending to be GPU evidence. Admission observes `adapter.info.isFallbackAdapter`; the actual subsequently selected device type remains unmeasured, so receipts say hardware-admitted WebGPU, not physical-device/performance proof.
